Our two improvements, measured in gem5

Both are new runtime options, so the paper's behaviour is unchanged when they are off. Time is the parallel region's simulated time divided by ws-numactl (work-stealing with every page interleaved, the paper's baseline). Below 1.00× is faster. Every run printed a correct result.

Improvement 1 · RT_STEAL_DIST=cost

NUMA cost-aware work stealing

The paper lets a node steal only when another queue holds more than distance × 6 tasks, and stops at the first such queue. With few tasks, far cores sit idle. Our rule compares time against time:

steal from node i if   backlogi × Ttask / 6  >  92 × Σj linesj × (hops(me, j) − hops(i, j))

backlog = queued tasks minus idle cores of node i; Ttask = measured average task time (before the first task ends: lines × 151 cycles); 92 cycles is the measured cost of one hop.

Improvement 2 · OMP_DATA_DISTRIBUTION=adaptive

Data distribution chosen by evidence

Choosing fine or coarse by hand is easy to get wrong (Matmul with fine runs 1.49×). The runtime now starts from fine and switches an allocation to coarse only with evidence:

coarse if   size < 8 pages   or   touched / (tasks × size) ≥ 0.5   else fine

A quick profile run (RT_PROFILE_OUT) records, per allocation, how many tasks list it and how many bytes each lists; the gem5 run reads it back (RT_PROFILE_IN). Pages are never moved, so the gem5 NUMA patch is unchanged.

Grey: hand-picked fine. Dark: hand-picked coarse. Green: adaptive (its choice in brackets). It matches the best hand pick on 4 of 6, and misses on Jacobi (+3.7%) and Reduction (+8.3%), where coarse happened to be faster than the paper's guidance.
